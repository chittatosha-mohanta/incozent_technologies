Process

The Complete Collection Workflow

Every project — whether a small pilot or a large-scale program — follows the same ten-step operational workflow, with customer input and defined outputs at every stage.

Define a Collection Project Start a Pilot
01

Customer Requirement

The customer provides the target data type, intended model use, geography, participant requirements, capture conditions, metadata, annotation and delivery expectations.

Customer InputModel use case, target data type, constraints
OutputA preliminary project specification
02

Collection Design

We translate the specification into a concrete collection design: participant profiles, environments, devices, activities, sample sizes and metadata schema.

Customer InputReview and approval of the design
OutputA detailed collection design document
03

Recruitment

Participants matching the defined demographic, geographic and device criteria are identified and screened for eligibility.

Customer InputDemographic and eligibility criteria
OutputA qualified participant pool
04

Consent

Each participant is presented with a defined-purpose consent process before any data is captured, covering usage, retention and deletion rights.

Customer InputPurpose and usage terms for the consent notice
OutputSigned, project-specific consent records
05

Data Collection

Collection is carried out according to the approved design — capturing images, video or activity data under the specified conditions.

Customer InputApproval of pilot samples, if applicable
OutputRaw collected data with capture metadata
06

Curation

Raw data is reviewed, filtered and organized — removing invalid, duplicate or non-compliant samples before annotation.

Customer InputCuration criteria, if project-specific
OutputA curated dataset ready for annotation
07

Annotation

Labels, tags, bounding boxes, keypoints or other annotations are applied according to the customer's schema and guidelines.

Customer InputAnnotation schema and guidelines
OutputAn annotated dataset
08

Quality Control

The dataset is reviewed against defined quality criteria, including completeness, annotation accuracy and metadata consistency.

Customer InputAcceptance criteria
OutputA quality-control report and corrected dataset
09

Privacy and Security Review

A project-specific privacy review confirms consent coverage, data minimization and secure handling before delivery.

Customer InputAny additional compliance requirements
OutputA privacy and security sign-off
10

Dataset Delivery

The final dataset is packaged and delivered in the agreed format, along with documentation, licensing and metadata files.

Customer InputDelivery format and destination
OutputThe delivered dataset and documentation
